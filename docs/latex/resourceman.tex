\chapter{Resource Management }
\hypertarget{resourceman}{}\label{resourceman}\index{Resource Management@{Resource Management}}
Resources and resource management are both very crucial components of Solaris. You will encounter a lot of Solaris components which you\textquotesingle{}ll need to assign resource(s) to for them to function properly.\hypertarget{resourceman_resourceman-resource}{}\doxysection{\texorpdfstring{Resources}{Resources}}\label{resourceman_resourceman-resource}
A resource is any memory block which Solaris does not explicitly define its size. Some of the things that fall in this category are: texture data, mesh data, an array of integers, shader source code, etc. to name a few.

To define a resource in Solaris, you must use the {\ttfamily Resource} or {\ttfamily Casted\+Resource} type. The difference between these two resource types will be explained further on.

\hypertarget{resourceman_resourceman-typename-resource}{}\doxysubsection{\texorpdfstring{The Resource Type}{The Resource Type}}\label{resourceman_resourceman-typename-resource}
The {\ttfamily Resource} type is conventionally used for resources with unspecified data types, or as a generic resource type. Most Solaris functions will expect a resource with a known data type (e.\+g., the {\ttfamily Model} \doxysectlink{renderobject}{render object}{0} expects a {\ttfamily Casted\+Resource\texorpdfstring{$<$}{<}float\texorpdfstring{$>$}{>}} as its mesh data, and {\ttfamily Casted\+Resource\texorpdfstring{$<$}{<}unsigned char\texorpdfstring{$>$}{>}} as its texture). As such, one could say that the {\ttfamily Resource} type acts mostly as an intermediary type.\hypertarget{resourceman_resourceman-typename-castedresource}{}\doxysubsection{\texorpdfstring{The Casted\+Resource Type}{The Casted\+Resource Type}}\label{resourceman_resourceman-typename-castedresource}
The {\ttfamily Casted\+Resource} type is used for resources with known data types. {\ttfamily Casted\+Resource} accepts a {\ttfamily typename} template parameter, the value of which is used to determine the pointer type of the resource.

The two key differences between a {\ttfamily Casted\+Resource} and a {\ttfamily Resource} is that, first, unlike the {\ttfamily Resource} type, {\ttfamily Casted\+Resource} isn\textquotesingle{}t necessarily supposed to hold a {\ttfamily void} pointer to the resource; rather, it is up to the programmer to specify what type of resource the {\ttfamily Casted\+Resource} is pointing to; and second, instead of a {\ttfamily size} property, {\ttfamily Casted\+Resource} holds a {\ttfamily len} property which determines how many values the resource is holding. i.\+e., assuming the resource is an array, {\ttfamily len} is how many elements the array is holding\hypertarget{resourceman_resourceman-casting-resources}{}\doxysubsubsection{\texorpdfstring{Casting Resources}{Casting Resources}}\label{resourceman_resourceman-casting-resources}
Consider the following example of manually casting a {\ttfamily Resource} to a {\ttfamily Casted\+Resource\texorpdfstring{$<$}{<}int\texorpdfstring{$>$}{>}}.

\begin{DoxyAttention}{Attention}
It\textquotesingle{}s not recommended and heavily discouraged to manually cast a {\ttfamily Resource} type. Instead, one must use the {\ttfamily Cast\+Resource} function to do so, which will be expanded upon later.
\end{DoxyAttention}
